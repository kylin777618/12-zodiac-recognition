# 执行顺序（谁在第几步做什么）

> 一句话：**先做不依赖别人的事，再做要等别人的事。** 六个人 D0 就能同时开工，不用等谁。
> 日期按 2026 年秋季学期第 13–16 周排，实际周次请对照教学日历。

## 一、每个人都一样的 7 步（D0，30 分钟一次性做完）

| 步 | 动作 | 命令 / 入口 | 完成标志 |
| --- | --- | --- | --- |
| 1 | 接受仓库邀请 | GitHub 通知里点 `Accept invitation` | 能打开仓库页面 |
| 2 | 克隆到你自己的电脑 | `git clone https://github.com/kylin777618/12-zodiac-recognition.git` | 目录里能看到 `src/`、`docs/` |
| 3 | 建虚拟环境并装依赖 | `python -m venv .venv` → `.venv\Scripts\activate` → `pip install -r requirements.txt` | `pip list` 里有 torch |
| 4 | 环境体检 | `python scripts/check_env.py` | 输出一张表，贴到群里 |
| 5 | 建自己的分支 | `git checkout -b feat/{你的字母}-{模块}` | `git status` 显示在新分支 |
| 6 | 读三份文档再动手 | `docs/任务清单.md`、`docs/统一技术口径.md`、`configs/base.yaml` | 知道自己交付什么 |
| 7 | 群里报一句 | "X 环境已通，分支 feat/x-xxx" | 组长登记 |

> 第 3 步装不上就立刻说，不要自己折腾一晚上。CPU 也能跑，先把链路跑通。

## 三、合并与交稿顺序

**PR 合并顺序 = 依赖链**：`#1 B → #2 C → #3 D → #4 E → #5 F`。前一个没合，后一个 PR 不要合，否则 CI 引用不到模块。

**报告交稿顺序**：B（二、四.2）→ C/D（四.3）→ E（四.4、五）→ F（三、七、附录B）→ 组长（封面、四.1、六）统稿。原因是后写的章节要引用前面的数字。

## 四、三条纪律

1. **等数据 ≠ 闲着**：C/D/E/F 在 D0–D3 都有不依赖别人的活，谁在第 3 天还说"在等 B"，就是没读这张表。
2. **分支别活太久**：一个模块一个 PR，超过 5 天没合并就拆小。长时间分支最后一定冲突。
3. **卡壳 4 小时就上报**：说清楚"卡在哪一步、报什么错、试过什么"，比自己闷一整天快得多。
